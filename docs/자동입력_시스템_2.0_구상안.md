# ERP 자동입력 시스템 2.0 구상안

> 작성일: 2026-08-18
> 대상: 존슨일렉트릭오퍼레이션스 ERP (`AngKor.Ylw.*` — 영림원소프트랩 K-System 계열로 추정)
> 목표: 특정 폴더의 소스파일을 읽어 **부서별로 서로 다른 ERP 메뉴/항목**에 야간 무인 자동입력

---

## 0. 요약 (먼저 읽을 것)

핵심 제안은 세 가지입니다.

| # | 제안 | 이유 |
|---|---|---|
| 1 | **입력 경로를 "어댑터"로 분리**하고, 벤더 인터페이스 → 그리드 붙여넣기 → UIA 화면입력 순으로 우선 적용 | GUI 자동화는 가장 불안정한 방법입니다. 더 좋은 길이 있으면 그 길로 가고, 없을 때만 GUI를 씁니다. 어댑터로 감싸두면 나중에 API가 생겨도 **나머지 코드를 안 고칩니다.** |
| 2 | **좌표 클릭(`click_input`) / `type_keys` / `time.sleep` 방식을 폐기**하고 UIA 패턴 직접 호출로 전환 | 현행 방식은 마우스·키보드를 점유하고, 창 위치·화면 잠금·포커스에 전부 의존합니다. 무인 야간 실행과 근본적으로 맞지 않습니다. |
| 3 | **부서/메뉴별 입력 정의를 코드가 아닌 YAML "레시피"로** 관리 | 부서마다 메뉴와 항목이 다릅니다. 메뉴 하나 늘 때마다 파이썬 코드를 새로 짜는 구조로는 유지가 안 됩니다. |

그리고 **가장 먼저 확인해야 할 것 하나**: 이 ERP는 영림원 K-System 계열로 보이며, 이 계열은 통상 **화면별 엑셀 업로드**와 **OpenAPI/인터페이스 테이블**을 제공합니다. 이게 열려 있으면 이 프로젝트의 90%는 필요 없어집니다. 착수 전 IT팀/벤더 확인을 권합니다. (→ 10장 질문 1)

## 1. 현행 시스템 진단

`attendance_auto.py` 기준입니다.

| 항목 | 현행 | 문제 | 2.0 개선 |
|---|---|---|---|
| 대상 범위 | 근태 화면 1개 하드코딩 | 부서·메뉴 확장 불가 | YAML 레시피로 메뉴 N개 |
| 입력 방식 | `click_input()` + `type_keys()` | 마우스/키보드 점유, 창 위치·포커스 의존, 화면 잠기면 실패 | UIA 패턴(`SetValue`/`Select`/`Invoke`) 직접 호출 |
| 대기 | `time.sleep(0.3~1.5)` 고정 | 느리면 실패, 빠르면 낭비. 건당 ~12초 | 조건부 대기(`wait("exists enabled ready")`) → 건당 2~4초 목표 |
| 저장 확인 | 없음 (클릭 후 바로 성공 처리) | **저장 실패를 성공으로 기록** | 저장 후 성공 메시지/키 발번 검증 |
| 중복 방지 | 없음 | 재실행 시 이중 등록 | dedupe key + SQLite 이력 |
| 메뉴 이동 | 없음 (사람이 미리 열어둠) | 무인 실행 불가 | 프로그램 검색창/트리 자동 이동 |
| 로그인/실행 | 없음 | 무인 실행 불가 | 세션 매니저가 실행·로그인·복구 |
| 팝업 처리 | 없음 | 예상 밖 모달 뜨면 무한 대기 or 오입력 | 팝업 감시자 + 즉시 중단 |
| 운영 | 콘솔 출력 + 실패 엑셀 | 야간 무인 시 아무도 모름 | 구조화 로그 + 리포트 + 알림 |
| 소스 | `근태입력.xlsx` 고정 | 부서별 파일 처리 불가 | inbox 폴더 스캔 |

정리하면, **현행은 "사람이 지켜보며 돌리는 보조 스크립트"로는 잘 만들어졌지만, 무인 운영에 필요한 요소가 구조적으로 빠져 있습니다.** 2.0은 기능 추가가 아니라 골격 교체로 접근하는 게 맞습니다.

## 2. 입력 경로 비교 — "더 좋은 방법"

GUI 자동화는 **최후의 수단**입니다. 아래 순서로 검토하고, 부서/메뉴마다 가능한 가장 높은 등급을 씁니다. (메뉴별로 등급이 달라도 됩니다.)

| 등급 | 방법 | 속도 | 안정성 | 전제조건 | 판단 |
|---|---|---|---|---|---|
| **A** | 벤더 제공 **OpenAPI / 웹서비스 / 인터페이스(스테이징) 테이블** | 최상 (초당 수십 건) | 최상 | 벤더 라이선스·승인 | **가능하면 무조건 이것.** ERP 검증 로직을 그대로 타므로 데이터 정합성도 보장 |
| **B** | 화면 내장 **엑셀 업로드 / 그리드 붙여넣기** | 상 (건당 <1초) | 상 | 해당 화면이 지원해야 함 | K-System 계열 다수 화면이 지원. **GUI 자동화로 "업로드 버튼 누르기"만 하면 되므로 A 다음으로 좋음** |
| **C** | **UIA 패턴 기반 화면 입력** (권장 GUI 방식) | 중 (건당 2~4초) | 중상 | UIA 트리 노출 (✅ 확인됨) | A/B 불가 시 표준안 |
| D | 좌표 클릭 + 키 입력 (현행) | 하 (건당 ~12초) | 하 | 화면 활성·잠금 해제 | **폐기.** C가 안 되는 일부 컨트롤의 폴백으로만 사용 |
| X | DB 직접 INSERT | 최상 | — | — | **권장하지 않음.** 유지보수 계약 위반·데이터 무결성 붕괴 위험. 벤더 승인 없이는 금지 |
| Y | 상용 RPA (UiPath 등) | 중 | 중상 | 라이선스 비용 | 파이썬 내재화가 목적이면 불필요. 다만 사내에 Power Automate가 이미 있으면 검토 가치 있음 |

**어댑터 설계의 핵심**: 레시피에 `adapter: api | grid_paste | uia` 한 줄만 바꾸면 경로가 바뀌고, 스케줄러·로그·검증·알림은 공통으로 재사용합니다. 지금은 C로 시작하더라도 A가 열리는 순간 이관 비용이 거의 없습니다.

## 4. 레시피(Recipe) 설계 — 부서/메뉴 확장의 핵심

메뉴 하나 = YAML 파일 하나. 파이썬 코드는 건드리지 않습니다.

```yaml
# app/recipes/HR_ATT.yaml
id: HR_ATT
name: 인사팀 - 근태계획 입력
department: 인사팀
adapter: uia                      # api | grid_paste | uia

navigate:
  method: program_search          # 상단 검색창(PART_txtPgmSearch) 이용 — 가장 견고
  keyword: "근태계획"
  expect_window: "근태계획"        # 열림 확인용 앵커 컨트롤/타이틀
  # method: menu_tree             # 대안: cmbModule + treeview 경로 클릭
  #   module: 인사
  #   path: [근태관리, 근태계획등록]

toolbar:
  container: { auto_id: tbToolBar, control_type: ToolBar }
  new:    "신규"
  save:   "저장"
  print:  { auto_id: Print, control_type: Button }   # 선택

source:
  sheet: 근태입력
  header_row: 1

# 엑셀 컬럼 → ERP 컨트롤 매핑
# type은 auto_id 접두어(txt/cmb/dat/msk/flt)로 자동 추론되므로 보통 생략 가능
fields:
  - { column: 사원명,   auto_id: txtEmpName,        required: true }
  - { column: 근태,     auto_id: cmbUMItemTypeName, required: true,
      allowed: [사용외출, 공용외출, 출장, 조퇴, 월차휴가, 년차휴가, 오전반차, 오후반차] }
  - { column: 사유,     auto_id: txtDescription,    max_length: 100 }
  - { column: 시작일,   auto_id: datStartDate,      format: "%Y%m%d", required: true }
  - { column: 시작시간, auto_id: mskStartTime,      format: "%H%M",   required: true }
  - { column: 종료일,   auto_id: datEndDate,        format: "%Y%m%d", required: true }
  - { column: 종료시간, auto_id: mskEndTime,        format: "%H%M",   required: true }
  - { column: 배차여부, auto_id: cmbUMCarUseName,   allowed: [예, 아니오] }
  - { column: 연락처,   auto_id: txtCellPhone,      pattern: '^\d{2,3}-\d{3,4}-\d{4}$' }

rules:
  - name: 종료일시는 시작일시 이후
    expr: "(종료일, 종료시간) >= (시작일, 시작시간)"

# 재실행해도 같은 건이 두 번 들어가지 않도록
dedupe_key: [사원명, 시작일, 시작시간, 근태]

save_verify:
  # 저장 성공을 무엇으로 판단할지 — 이게 없으면 실패를 성공으로 기록함
  any_of:
    - toast_text: "저장되었습니다"
    - field_filled: txtRefNo        # 저장 시 채번되는 필드
  on_dialog:
    "확인": accept                  # 정상 확인 팝업
    "이미 등록": skip_as_duplicate  # 중복 경고는 실패가 아닌 스킵으로
    "*": abort                      # 그 외 예상 밖 팝업 → 전체 중단
```

부서가 추가되면 이 YAML 하나만 작성하면 됩니다. 신규 메뉴 온보딩은 `dump_controls.py`(현행 자산 그대로 활용)로 `auto_id`를 뽑아 매핑표를 채우는 작업으로 단순화됩니다.

## 5. GUI 어댑터 개선 (등급 C) — 가장 큰 기술적 변화

`controls.txt` 분석 결과 이 ERP는 WPF이고 컨트롤이 UIA 트리에 정상 노출됩니다. 따라서 **마우스·키보드를 전혀 쓰지 않고** 값을 넣을 수 있습니다.

### 5.1 3단 폴백 쓰기 전략

```python
def write(ctrl, value):
    # 1단: UIA ValuePattern — 포커스·창 위치·화면 잠금과 무관, 즉시 반영
    try:
        ctrl.iface_value.SetValue(str(value)); return
    except Exception:
        pass
    # 2단: 키보드 입력 (창 활성 필요, 마우스는 불필요)
    try:
        ctrl.set_focus(); ctrl.type_keys("^a{DEL}"); ctrl.type_keys(str(value), with_spaces=True); return
    except Exception:
        pass
    # 3단: 좌표 클릭 (현행 방식 — 최후 수단)
    ctrl.click_input(); ...
```

컨트롤별 매핑:

| 접두어 | 컨트롤 | 1단 방식 |
|---|---|---|
| `txt*` | Edit (`textBox1`) | `ValuePattern.SetValue` |
| `cmb*` | ComboBox | `ComboBoxWrapper.select(값)` → 내부적으로 `SelectionItemPattern.Select` (드롭다운 여는 클릭 불필요) |
| `dat*` | 날짜 Edit (`EditDate1`) | `SetValue("20260408")` |
| `msk*` | 마스크 Edit | `SetValue("0900")` |
| `flt*` | 숫자 | `SetValue` |
| 버튼/툴바 | Button | `InvokePattern.Invoke()` — 클릭 좌표 불필요 |

**효과**: 마우스 점유 없음 / 창이 뒤에 있어도 동작 / 화면 잠김에 훨씬 강함 / 속도 3~5배.

### 5.2 고정 sleep 제거

```python
# 현행
btn.click_input(); time.sleep(1.5)

# 2.0
btn.invoke()
win.child_window(auto_id="txtEmpName").wait("exists enabled visible ready", timeout=15)
```

건당 처리시간이 약 12초 → 2~4초로 줄고, 느린 날에도 실패하지 않습니다.

### 5.3 저장 검증 (필수)

현행의 가장 큰 리스크는 **저장 버튼을 눌렀지만 실제로 저장되지 않은 건을 성공으로 기록**하는 것입니다. 야간 무인이면 아무도 못 잡습니다. 레시피의 `save_verify`로 성공 근거를 확인한 뒤에만 성공 처리하고, 확인 불가 시 스크린샷을 남기고 실패로 분류합니다.

### 5.4 팝업 감시자

별도 스레드에서 예상 밖 모달 다이얼로그를 감시합니다. 레시피에 정의되지 않은 팝업이 뜨면 → 스크린샷 저장 → 즉시 중단 → 알림. **모르는 팝업에 엔터를 치지 않는 것**이 무인 운영의 안전 원칙입니다.

## 6. 무인 야간 실행 — 화면보호기·잠금·전원

가장 많이 실패하는 지점입니다. UI 자동화는 **대화형 세션이 살아 있어야** 하고, 세션이 잠기면(Lock) 상당수 동작이 실패합니다. 5중으로 막습니다.

### 6.1 Windows 설정 (1회 세팅)

```powershell
# 화면 끄기/절전 해제 (AC 전원 기준)
powercfg /change monitor-timeout-ac 0
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change disk-timeout-ac 0

# 화면보호기 비활성화
reg add "HKCU\Control Panel\Desktop" /v ScreenSaveActive /t REG_SZ /d 0 /f
reg add "HKCU\Control Panel\Desktop" /v ScreenSaverIsSecure /t REG_SZ /d 0 /f
reg add "HKCU\Control Panel\Desktop" /v ScreenSaveTimeOut /t REG_SZ /d 0 /f

# 유휴 시 자동 잠금 해제 (0 = 잠그지 않음)
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System" ^
        /v InactivityTimeoutSecs /t REG_DWORD /d 0 /f
```

> ⚠️ 회사 그룹정책(GPO)이 화면보호기·자동잠금을 강제하면 위 레지스트리는 정책에 덮어써집니다. 이 경우 **해당 PC를 정책 예외 OU로 빼는 협의가 필수**입니다. (→ 10장 질문 4)

### 6.2 프로그램 자체 각성 유지 (`awake.py`)

정책과 무관하게, 실행 중에는 프로그램이 직접 시스템에 "자지 마"라고 선언합니다.

```python
import ctypes
ES_CONTINUOUS, ES_SYSTEM_REQUIRED, ES_DISPLAY_REQUIRED = 0x80000000, 0x00000001, 0x00000002

def keep_awake():   # 실행 시작 시
    ctypes.windll.kernel32.SetThreadExecutionState(
        ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)

def release():      # 종료 시 원복
    ctypes.windll.kernel32.SetThreadExecutionState(ES_CONTINUOUS)
```

이 방식은 마우스를 흔드는 꼼수보다 정확하고, 보안 정책 위반 소지도 없습니다.

### 6.3 작업 스케줄러 설정

| 설정 | 값 | 이유 |
|---|---|---|
| 보안 옵션 | **"사용자가 로그온한 경우에만 실행"** | ★ "로그온 여부 관계없이 실행"을 고르면 세션 0에서 돌아 **GUI 자동화가 100% 실패**합니다 |
| 권한 | 가장 높은 권한으로 실행 | ERP 창 접근 |
| 조건 | "이 작업을 실행하기 위해 절전 모드 해제" ✅ | 절전 진입 시 복귀 |
| 조건 | "컴퓨터를 AC 전원으로 사용하는 경우에만" ❌ 해제 | 노트북 대응 |
| 설정 | 실패 시 1분 후 3회 재시도 | 일시 오류 복구 |
| 설정 | 3시간 초과 시 강제 종료 | 무한 대기 방지 |

### 6.4 재부팅 복구

Windows 업데이트 등으로 재부팅되면 로그오프 상태가 되어 자동화가 죽습니다.
→ **자동 로그온 설정**(Sysinternals `Autologon`, 자격증명 LSA 암호화 저장) + 로그온 트리거 작업으로 세션 복구.
→ 단, 자동 로그온 PC는 **물리적 접근 통제가 되는 곳**에 두어야 합니다. (→ 10장 질문 4)

### 6.5 원격접속(RDP) 주의

RDP로 접속했다가 그냥 창을 닫으면 **세션이 잠기면서 자동화가 실패**합니다. 운영 PC는 콘솔 세션을 유지해야 하며, 원격 점검이 필요하면 접속 후 `tscon`으로 콘솔에 세션을 되돌려주는 절차를 운영 수칙에 넣습니다. 가급적 **전용 PC(미니PC/VM)를 두고 아무도 로그오프하지 않는 것**이 가장 안전합니다.

### 6.6 사전 점검(Preflight)

본 실행 10분 전에 별도 작업으로 돌립니다.

- 세션 잠금 여부 / ERP 실행·로그인 가능 여부 / inbox 파일 존재·형식 / 디스크 여유 / 이전 실행 잔여 프로세스
- 문제가 있으면 **본 실행 전에** 담당자에게 알림 → 아침에 "아무것도 안 돌았네"를 방지

## 7. 안전장치 (무인이라 필수)

| 장치 | 내용 |
|---|---|
| **Dry-run 모드** | ERP에 값만 채우고 저장하지 않음. 신규 레시피는 반드시 dry-run 통과 후 운영 투입 |
| **중복 입력 방지** | `dedupe_key` 해시를 SQLite에 유니크 저장. 같은 파일을 두 번 넣어도 재입력 안 됨 |
| **처리 건수 상한** | 1회 실행 최대 N건(예: 300). 초과 시 중단+알림 (소스파일 사고 방지) |
| **킬스위치** | `C:\ERP_Auto\STOP.flag` 파일이 있으면 즉시 중단. 원격에서 파일 하나로 정지 |
| **연속 실패 차단** | 3건 연속 실패 시 전체 중단. 잘못된 상태로 100건을 밀어넣지 않음 |
| **예상 밖 팝업 → 중단** | 5.4 참조 |
| **워치독 타임아웃** | 1건 60초 초과 시 해당 건 포기·화면 복구(ESC)·다음 건 진행 |
| **원본 불변** | 소스파일은 절대 수정하지 않고 `processed\`로 이동만 |
| **입력 전 백업 권고** | 대량 입력 전 ERP 측 데이터 백업 시점 확인 (운영 수칙) |

- **로그**: `logs\2026-08-18.log` (JSON Lines). 건별 recipe/row/결과/소요시간/오류. **개인정보(연락처·사번)는 마스킹.**
- **스크린샷**: 실패 시점만 저장, 30일 후 자동 삭제.

## 9. 단계별 로드맵

| 단계 | 내용 | 산출물 | 예상 |
|---|---|---|---|
| **0. 타당성 확인** | 벤더 API/엑셀업로드 존재 여부 확인 (10장 질문 1) | 경로 결정 | 1주 |
| **1. 골격 구축** | 어댑터 구조 + UIA 패턴 입력 + 레시피 로더 + 상태DB. **기존 근태 화면을 레시피로 재현**해 현행과 결과 동일함을 검증 | 근태 레시피 동작 | 2주 |
| **2. 무인화** | 세션 매니저(실행·로그인) + 각성 유지 + 스케줄러 + preflight + 알림 | 야간 자동 실행 | 1~2주 |
| **3. 안전장치** | 저장 검증 · 팝업 감시 · 중복 방지 · 킬스위치 · 리포트 | 운영 투입 가능 | 1주 |
| **4. 부서 확산** | 부서별 레시피 추가 (부서당 1~3일). dry-run → 소량 병행 → 전면 | 메뉴 N개 | 부서별 |
| **5. 고도화** | 등급 A/B 어댑터 이관, 웹 대시보드, 셀프서비스 업로드 | — | 선택 |

**리스크 관리**: 각 부서 확산 시 최소 1주는 **기존 수기 입력과 병행**하며 결과를 대조한 뒤 자동화 단독으로 전환할 것을 권합니다. ERP 데이터는 되돌리기가 어렵습니다.

## 10. 확인이 필요한 사항

가장 중요한 것부터입니다.

1. **★ 벤더 인터페이스 존재 여부** — 이 ERP(영림원 K-System 계열로 추정)에 ① 화면별 엑셀 업로드, ② 그리드 붙여넣기, ③ OpenAPI/인터페이스 테이블 중 사용 가능한 게 있는지 IT팀/벤더에 확인 가능할까요? 하나라도 되면 설계가 크게 단순해집니다.
2. **대상 부서와 메뉴 목록** — 어떤 부서가 어떤 메뉴에 무엇을 입력하는지 (부서 수 / 메뉴 수 / 일 평균 건수). 건수가 하루 수천 건이면 등급 C(GUI)로는 야간 시간 안에 못 끝낼 수 있습니다.
3. **ERP 로그인 방식** — ID/PW 직접입력인지, Windows 통합인증(SSO)인지, OTP/2차 인증이 있는지. 자동 로그인 가능 여부가 무인화의 전제입니다.
4. **운영 PC 환경** — 전용 PC를 둘 수 있는지, 그룹정책(화면보호기·자동잠금·자동 로그온)을 예외 처리할 수 있는지, 물리 보안이 되는 위치인지.
5. **소스파일과 알림** — 부서별 파일 양식을 **표준 엑셀 하나로 통일** 가능한지(강력 권장), 아니면 부서 기존 양식을 그대로 받아야 하는지. 알림은 메일/Teams 중 무엇인지.
6. **야간 실행이 요건인지 선호인지** — 등급 C로 전환하면 건당 2~4초라 업무시간 백그라운드 실행도 가능합니다. 야간을 고수하는 이유가 "업무 방해 회피"라면 야간 유지가 맞고, "ERP 부하"라면 사실상 무관합니다.
7. **실패 시 처리 정책** — 1건 실패 시 나머지를 계속 진행할지, 전체 중단할지. 부서마다 다를 수 있습니다.
