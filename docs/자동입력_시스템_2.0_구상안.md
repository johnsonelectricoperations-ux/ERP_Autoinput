## 0. 확정된 전제 (사용자 확인 완료)

| # | 확인 사항 | 답변 | 설계에 미치는 영향 |
|---|---|---|---|
| 1 | 벤더 대량입력 수단 (API/엑셀업로드) | **사용 불가** | **GUI 자동화(UIA)로 확정.** 단, 화면 자체가 지원하는 그리드 붙여넣기는 메뉴별로 계속 탐색 |
| 2 | ERP 로그인 | ERP 첫 화면에서 **ID/PW 직접 입력**, PC 비밀번호와 별개 | SSO 아님 → **로그인 자동화 모듈이 별도로 필요.** OTP가 없으므로 자동화 가능 |
| 3 | 운영 PC 화면보호기 | **일정 시간 후 자동 실행됨.** OS 설정은 그대로 두고, 마우스를 주기적으로 움직여 실행 중에만 방지 | **각성 유지 모듈이 필수 구성요소.** GPO 협의 불필요. 6장에서 전용 설계 |
| 4 | 소스파일 양식 | 부서별 공용폴더에 각각의 양식, **양식은 새로 개발해도 됨** | **레시피(YAML)에서 엑셀 양식을 자동 생성**하는 구조로 설계. 양식·검증·입력이 한 정의에서 파생 |

### 이번 개정의 핵심 결론 3가지

1. **입력 방식은 UIA 패턴 직접 호출로 전환한다.** 현행 `click_input`/`type_keys`는 마우스를 점유하는데, 3번(화면보호기 방지용 마우스 움직임)과 **정면으로 충돌**합니다. 마우스를 쓰지 않는 방식으로 가야 두 기능이 공존합니다. 대신 UIA 패턴은 입력 이벤트를 발생시키지 않아 **Windows 유휴 타이머를 리셋하지 않으므로, 각성 유지를 실행 전 구간 상시로 켜두어야 합니다** (6.3).
2. **레시피 YAML을 단일 진실 원천(Single Source of Truth)으로 삼는다.** 부서 양식 엑셀 생성 · 데이터 검증 · ERP 입력이 전부 같은 파일 하나에서 나옵니다. 부서가 늘어도 파이썬 코드는 안 건드립니다.
3. **로그인과 각성 유지가 무인 운영의 두 급소다.** 이 둘이 실패하면 나머지가 아무리 완벽해도 아침에 "아무것도 안 돌았음"이 됩니다. 각각 3중 방어 + 사전점검을 겁니다.

## 1. 현행 시스템 진단

`attendance_auto.py` 기준입니다.

| 항목 | 현행 | 문제 | 2.0 개선 |
|---|---|---|---|
| 대상 범위 | 근태 화면 1개 하드코딩 | 부서·메뉴 확장 불가 | YAML 레시피로 메뉴 N개 |
| 입력 방식 | `click_input()` + `type_keys()` | 마우스/키보드 점유 → **각성 유지 기능과 충돌**, 창 위치·포커스 의존 | UIA 패턴(`SetValue`/`Select`/`Invoke`) 직접 호출 |
| 대기 | `time.sleep(0.3~1.5)` 고정 | 느리면 실패, 빠르면 낭비. 건당 약 12초 | 조건부 대기(`wait("exists enabled ready")`) → 건당 2~4초 |
| 저장 확인 | 없음 (클릭 후 즉시 성공 처리) | **저장 실패를 성공으로 기록** | 저장 후 성공 근거 검증 |
| 중복 방지 | 없음 | 재실행 시 이중 등록 | dedupe key + SQLite 이력 |
| 메뉴 이동 | 없음 (사람이 미리 열어둠) | 무인 실행 불가 | 프로그램 검색창으로 자동 이동 |
| 로그인 | 없음 | 무인 실행 불가 | 로그인 자동화 모듈 (7장) |
| 화면보호기 | 없음 | 야간에 화면보호기 → 자동화 정지 | 각성 유지 모듈 (6장) |
| 팝업 처리 | 없음 | 예상 밖 모달에 무한 대기 | 팝업 감시자 + 즉시 중단 |
| 소스 | `근태입력.xlsx` 고정 | 부서별 파일 처리 불가 | 공용폴더 스캔 |
| 운영 | 콘솔 출력 + 실패 엑셀 | 야간에 아무도 모름 | 구조화 로그 + 리포트 + 알림 |

현행은 **사람이 지켜보며 돌리는 보조 스크립트**로는 잘 만들어졌습니다. 2.0은 기능 추가가 아니라 **골격 교체**로 접근하는 것이 맞습니다. 다만 `dump_controls.py`(컨트롤 덤프)와 `make_template.py`(양식 생성)는 개념이 그대로 살아나므로 확장 재사용합니다.

## 3. 레시피(Recipe) — 부서 확장의 핵심

메뉴 하나 = YAML 하나. 파이썬 코드는 건드리지 않습니다.
이 파일 하나에서 **① 부서 양식 엑셀 ② 검증 규칙 ③ ERP 입력 절차**가 전부 파생됩니다.

```yaml
# app/recipes/HR_ATT.yaml
id: HR_ATT
version: 1
name: 인사팀 - 근태계획 입력
department: 인사팀
inbox: '\\서버\ERP입력\인사팀'

navigate:
  method: program_search        # 상단 검색창(PART_txtPgmSearch) — 가장 견고
  keyword: "근태계획"
  expect: { auto_id: txtEmpName }   # 이 컨트롤이 보이면 화면이 열린 것
  # 대안) method: menu_tree  /  module: 인사  /  path: [근태관리, 근태계획등록]

toolbar:
  container: { auto_id: tbToolBar, control_type: ToolBar }
  new:  "신규"
  save: "저장"
  print: { auto_id: Print, control_type: Button }    # 선택

# 엑셀 컬럼 ↔ ERP 컨트롤 매핑.
# type은 auto_id 접두어(txt/cmb/dat/msk/flt)로 자동 추론되므로 보통 생략
fields:
  - { column: 사원명,   auto_id: txtEmpName,        required: true, width: 12 }
  - { column: 근태,     auto_id: cmbUMItemTypeName, required: true, width: 12,
      allowed: [사용외출, 공용외출, 출장, 조퇴, 월차휴가, 년차휴가, 오전반차, 오후반차] }
  - { column: 사유,     auto_id: txtDescription,    max_length: 100, width: 20 }
  - { column: 시작일,   auto_id: datStartDate,      required: true, format: "%Y%m%d", width: 14 }
  - { column: 시작시간, auto_id: mskStartTime,      required: true, format: "%H%M",   width: 10 }
  - { column: 종료일,   auto_id: datEndDate,        required: true, format: "%Y%m%d", width: 14 }
  - { column: 종료시간, auto_id: mskEndTime,        required: true, format: "%H%M",   width: 10 }
  - { column: 배차여부, auto_id: cmbUMCarUseName,   allowed: [예, 아니오], width: 10 }
  - { column: 연락처,   auto_id: txtCellPhone,      pattern: '^\d{2,3}-\d{3,4}-\d{4}$', width: 16 }

rules:
  - { name: 종료일시는 시작일시 이후, expr: "(종료일,종료시간) >= (시작일,시작시간)" }

dedupe_key: [사원명, 시작일, 시작시간, 근태]   # 재실행해도 중복 입력 안 되게

save_verify:                    # 저장 성공 근거 (없으면 실패를 성공으로 오인함)
  any_of:
    - toast_text: "저장되었습니다"
    - field_filled: txtRefNo    # 저장 시 채번되는 필드
  on_dialog:
    "확인": accept
    "이미 등록": skip_as_duplicate
    "*": abort                  # 정의되지 않은 팝업 → 전체 중단
```

### 3.1 양식 엑셀 자동 생성 (`make-template`)

> 사용자 답변 4번("양식은 인식하기 편하도록 개발해도 된다")을 반영한 설계입니다.

```
python main.py make-template --recipe HR_ATT --out "\\서버\ERP입력\인사팀\[양식] 근태계획.xlsx"
```

레시피의 `fields`를 읽어 아래를 자동 생성합니다. `make_template.py`의 방식을 그대로 확장한 것입니다.

- 헤더 행 (색상·굵게·열너비 = 레시피의 `width`)
- **`allowed` 값 → 드롭다운 자동 생성** (오타 원천 차단)
- **`format` → 셀 서식 지정** (날짜/시간 형식 강제)
- **`required` → 헤더에 `*` 표시 + 조건부 서식으로 빈칸 강조**
- 샘플 1행 + 작성 안내 시트
- **숨김 메타 시트**에 `recipe_id` / `version` 기록 → 파일명이 바뀌어도 어느 레시피인지 확실히 인식

이 방식의 이점: **양식과 프로그램이 절대 어긋나지 않습니다.** 레시피에 컬럼을 하나 추가하면 양식·검증·입력이 동시에 따라옵니다. 양식과 코드를 따로 관리하면 반드시 어긋나고, 그 사고는 야간에 조용히 일어납니다.

### 3.2 공용폴더 처리 규칙

| 상황 | 처리 |
|---|---|
| 담당자가 엑셀을 열어둔 상태 (`~$*.xlsx` 락 파일 존재) | 이번 회차 **스킵**, 다음 실행에 처리 (읽는 중 저장돼 깨지는 것 방지) |
| 파일 수정시각이 5분 이내 | 스킵 (복사 중일 수 있음) |
| `[양식]`으로 시작하는 파일 | 원본 양식이므로 처리 대상에서 제외 |
| 메타 시트의 `version`이 현재 레시피보다 낮음 | 구버전 양식 → 오류 처리 + 최신 양식 안내 알림 |
| 처리 완료 | 원본 수정 없이 `_완료\<날짜>\`로 이동 |
| 처리 실패 | `_오류\<날짜>\`로 이동 + **사유 시트를 덧붙인 사본** 생성 → 담당자가 바로 고칠 수 있게 |
| 네트워크 드라이브 접근 실패 | 3회 재시도 후 알림 (UNC 경로 직접 사용 권장. 드라이브 문자는 세션에 따라 안 잡힐 수 있음) |

## 4. UIA 어댑터 — 입력 방식 전환

`controls.txt` 분석 결과 이 ERP는 WPF이며 컨트롤이 UIA 트리에 정상 노출됩니다. 따라서 **마우스·키보드를 쓰지 않고** 값을 넣을 수 있습니다. 이것이 각성 유지(6장)와의 충돌을 없애는 핵심입니다.

### 4.1 3단 폴백 쓰기

```python
def write(ctrl, value):
    # 1단: UIA ValuePattern — 마우스·포커스·창 위치와 무관. 즉시 반영
    try:
        ctrl.iface_value.SetValue(str(value)); return "pattern"
    except Exception:
        pass
    # 2단: 키보드 입력 (창 활성 필요, 마우스는 불필요)
    try:
        ctrl.set_focus()
        ctrl.type_keys("^a{DEL}")
        ctrl.type_keys(str(value), with_spaces=True); return "keyboard"
    except Exception:
        pass
    # 3단: 좌표 클릭 (현행 방식 — 최후 수단, 각성 유지와 상호배제 필요)
    with awake.pause():
        ctrl.click_input(); ...
        return "click"
```

컨트롤별 매핑 (`auto_id` 접두어로 자동 판별):

| 접두어 | 컨트롤 | 1단 방식 |
|---|---|---|
| `txt*` | Edit (`textBox1`) | `ValuePattern.SetValue` |
| `cmb*` | ComboBox | `select(값)` → `SelectionItemPattern.Select` (드롭다운 여는 클릭 불필요) |
| `dat*` | 날짜 Edit (`EditDate1`) | `SetValue("20260408")` |
| `msk*` | 마스크 Edit | `SetValue("0900")` |
| `flt*` | 숫자 | `SetValue` |
| 버튼·툴바 | Button | `InvokePattern.Invoke()` — 좌표 불필요 |

**효과**: 마우스 점유 없음 / 창이 뒤에 있어도 동작 / 화면보호기 방지 기능과 공존 / 속도 3~5배.

> ⚠️ 검증 필요: WPF 마스크·날짜 컨트롤 일부는 `ValuePattern`을 노출하지 않을 수 있습니다. Phase 1에서 **컨트롤별로 어느 단계가 먹히는지 실측**해 레시피에 `write_mode`로 고정합니다. 3단(클릭)이 필요한 컨트롤이 있어도 상호배제로 처리 가능하므로 설계는 유효합니다.

### 4.2 고정 sleep 제거

```python
# 현행
btn.click_input(); time.sleep(1.5)

# 2.0
btn.invoke()
win.child_window(auto_id="txtEmpName").wait("exists enabled visible ready", timeout=15)
```

건당 약 12초 → 2~4초. 느린 날에도 실패하지 않습니다.

### 4.3 저장 검증 (필수)

현행의 최대 리스크는 **저장 버튼은 눌렀지만 실제로 저장되지 않은 건을 성공으로 기록**하는 것입니다. 야간 무인이면 아무도 못 잡습니다. `save_verify`의 근거를 확인한 뒤에만 성공 처리하고, 확인 불가 시 스크린샷을 남기고 실패로 분류합니다.

### 4.4 팝업 감시자

별도 스레드가 예상 밖 모달을 감시합니다. 레시피에 정의되지 않은 팝업이 뜨면 → 스크린샷 → 즉시 중단 → 알림. **모르는 팝업에 엔터를 치지 않는 것**이 무인 운영의 안전 원칙입니다.

```

                        └ 문제 발견 시 → 즉시 알림 (본 실행 전에 손쓸 수 있게)
─────────────────────────────────────────────────────────────
21:00  run
  1. awake.start()              각성 유지 시작 (종료 시까지 상시)
  2. 공용폴더 스캔              부서별 파일 수집 → 레시피 매칭

  4. 중복 제거                  state.db 대조
  5. ERP 실행 + 로그인          (7장)
  6. 레시피별 반복:
```

## 6. ★ 각성 유지 — 화면보호기·잠금·절전 (사용자 확인 3번)

> **"시간이 지나면 자동 화면보호기가 실행된다. 마우스가 일정시간에 조금씩 움직이게 해놔야 한다."**

말씀하신 방향이 맞습니다. 다만 **커서를 실제로 움직이면 자동화 입력과 충돌**할 수 있어, 같은 효과를 내면서 부작용이 없는 방식을 제안합니다. 3중으로 막습니다.

### 6.1 1차 — 시스템 절전/화면끄기 차단

```python
# core/awake.py
import ctypes
ES_CONTINUOUS       = 0x80000000
ES_SYSTEM_REQUIRED  = 0x00000001
ES_DISPLAY_REQUIRED = 0x00000002

def block_sleep():
    ctypes.windll.kernel32.SetThreadExecutionState(
        ES_CONTINUOUS | ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)

def restore():
    ctypes.windll.kernel32.SetThreadExecutionState(ES_CONTINUOUS)
```

절전 진입과 모니터 꺼짐을 막습니다. 단, **화면보호기는 유휴 시간 기준의 별도 메커니즘이라 이것만으로는 완전히 막히지 않습니다.** 그래서 2차가 필요합니다.

### 6.2 2차 — 유휴 타이머 리셋 (말씀하신 "마우스 움직임"의 안전한 구현)

```python
# 상대 이동 (0, 0) — 커서는 실제로 움직이지 않지만 유휴 타이머는 리셋됨
def nudge():
    ctypes.windll.user32.mouse_event(0x0001, 0, 0, 0, 0)   # MOUSEEVENTF_MOVE
```

**왜 커서를 실제로 움직이지 않는가:**

| 방식 | 화면보호기 방지 | 부작용 |
|---|---|---|
| 커서를 몇 픽셀 이동 | ✅ | 자동화가 클릭하려는 순간 커서가 밀림 → **오클릭 위험**. 드롭다운이 닫히기도 함 |
| 키 입력 (F15 등) | ✅ | 포커스된 ERP 입력칸에 **키가 들어갈 위험** |
| **상대이동 (0,0)** | ✅ | **없음.** 커서 위치 불변, 클릭·키 입력과 무간섭 |

- **주기**: 60초 (화면보호기 대기시간보다 충분히 짧게). `settings.yaml`에서 조정
- **상호배제**: 4.1의 3단(좌표 클릭) 실행 중에는 `awake.pause()`로 일시정지 → 만일의 충돌도 차단

### 6.3 언제 켜고 끄는가 — "가동 중에는 꺼도 되지 않나?"

> **"화면보호기는 시스템이 정해진 시간에 작동하게 하고, 그동안은 화면보호기가 실행 안 되도록 마우스를 조금씩 움직이게 한다. 시스템이 가동되면 필요 없으니 중지하면 된다."**

앞부분은 그대로 채택합니다. **OS·GPO 설정은 건드리지 않고 프로그램이 도는 동안만 막습니다.** 정책 협의가 필요 없고, 다른 시간대에는 회사 보안 정책이 정상 작동합니다.

뒷부분("가동되면 중지")은 **입력 방식에 따라 결론이 뒤집히므로** 주의가 필요합니다.

Windows의 유휴 타이머(화면보호기 발동 기준, `GetLastInputInfo`)는 **실제 입력 이벤트**가 있어야 리셋됩니다.

| 입력 방식 | 유휴 타이머 리셋 | 가동 중 각성 유지 |
|---|---|---|
| 현행 `click_input` / `type_keys` | ✅ 실제 마우스·키보드 이벤트 발생 | 불필요 |
| **2.0 UIA `ValuePattern.SetValue`** | ❌ 입력 큐를 거치지 않는 COM 호출 | **계속 필요** |

UIA 패턴 방식은 마우스·키보드를 전혀 쓰지 않는 것이 장점인데, **바로 그 이유로 Windows 입장에서는 "아무도 PC를 안 쓰는 상태"로 보입니다.** 자동화가 100건을 입력하며 30분간 돌아도 유휴 시간은 계속 쌓여 작업 도중에 화면보호기가 뜹니다.

게다가 현행 방식을 유지하더라도 아래 구간에는 입력이 없습니다.

- ERP 기동·로그인 대기 (60초 이상)
- 저장 후 서버 응답 대기
- 네트워크 공용폴더 스캔·파일 이동
- **리포트 생성 및 알림 발송** ← 입력 작업이 끝난 뒤라 가장 방심하기 쉬운 구간

**결론: 시작부터 종료까지 전 구간 상시 동작.**

```
awake.start()   ← 프로그램 시작 직후 (ERP 열기 전)
   │  60초마다 mouse_event(MOUSEEVENTF_MOVE, 0, 0)
   │  [ERP 실행 → 로그인 → 입력 → 저장 → 파일이동 → 리포트]
   │     └ 좌표 클릭 폴백 순간에만 awake.pause()
awake.stop()    ← 프로그램 종료 시 (이후 회사 정책대로 화면보호기 정상 작동)
```

"필요 없으면 중지"는 **전체 실행이 끝난 시점**에 적용합니다. 지글러 비용은 60초에 API 호출 한 줄이라 켜둬서 손해 볼 것이 없고, 반대로 껐다가 뜨면 그날 작업 전체가 멈춥니다.

### 6.4 3차 — 시스템 설정 (가능한 범위에서)

정책상 가능하다면 아래를 적용하면 훨씬 안전해집니다. **불가능해도 1·2차로 동작하도록 설계**합니다.

```powershell
powercfg /change monitor-timeout-ac 0
powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0

# 화면보호기 비활성화
reg add "HKCU\Control Panel\Desktop" /v ScreenSaveActive /t REG_SZ /d 0 /f
reg add "HKCU\Control Panel\Desktop" /v ScreenSaveTimeOut /t REG_SZ /d 0 /f
```

### 6.5 ⚠️ 가장 큰 위험: "다시 시작할 때 로그온 화면 표시"

**이 항목만은 반드시 확인해야 합니다.**

화면보호기 설정에 **"다시 시작할 때 로그온 화면 표시"(`ScreenSaverIsSecure`)** 가 켜져 있으면, 화면보호기 실행 = **세션 잠금**입니다. 세션이 잠기면 UI 자동화는 대부분 실패하며, 이건 마우스를 흔들어도 이미 늦은 상태입니다.

```powershell
# 반드시 0 이어야 함
reg query "HKCU\Control Panel\Desktop" /v ScreenSaverIsSecure
```

- `0`이면 → 화면보호기가 떠도 잠기지 않으므로 2차 방어로 충분합니다.
- `1`이고 끌 수 있으면 → 끕니다.
- `1`인데 **회사 GPO로 강제**되어 못 끄면 → 해당 PC를 **정책 예외 OU로 빼는 협의가 선행되어야** 합니다. 협의가 불가능하면 야간 무인 실행 자체가 성립하지 않으므로, 이 경우 **업무시간 중 백그라운드 실행**으로 방향을 바꾸는 것이 현실적입니다 (UIA 방식은 건당 2~4초, 마우스를 안 쓰므로 사람이 PC를 쓰는 중에도 병행 가능).

### 6.6 최후 방어 — 잠금 감지 후 중단

그래도 잠기는 상황을 대비해, 실행 중 주기적으로 세션 상태를 확인합니다.

```python
def is_locked():
    DESKTOP_SWITCHDESKTOP = 0x0100
    h = ctypes.windll.user32.OpenInputDesktop(0, False, DESKTOP_SWITCHDESKTOP)
    if not h:
        return True                     # 잠금 화면(Winlogon 데스크톱)이면 실패
    ctypes.windll.user32.CloseDesktop(h)
    return False
```

잠김이 감지되면 **입력을 멈추고 알림**을 보냅니다. 잠긴 채로 입력을 계속 시도해 데이터가 엉뚱하게 들어가는 것보다, 멈추고 보고하는 편이 훨씬 낫습니다.

### 6.7 작업 스케줄러 설정

| 설정 | 값 | 이유 |
|---|---|---|
| 보안 옵션 | **"사용자가 로그온한 경우에만 실행"** | ★ "로그온 여부 관계없이 실행"을 선택하면 세션 0에서 실행되어 **GUI 자동화가 100% 실패**합니다 |
| 권한 | 가장 높은 권한으로 실행 | ERP 창 접근 |
| 조건 | "작업을 실행하기 위해 절전 모드 해제" ✅ | 절전 진입 시 복귀 |
| 조건 | "AC 전원일 때만 실행" ❌ 해제 | 노트북 대응 |
| 설정 | 실패 시 1분 후 3회 재시도 | 일시 오류 복구 |
| 설정 | 3시간 초과 시 강제 종료 | 무한 대기 방지 |

**재부팅 대비**: Windows 업데이트로 재부팅되면 로그오프 상태가 되어 자동화가 죽습니다. 자동 로그온(Sysinternals `Autologon`, 자격증명 LSA 암호화 저장)을 걸어두면 복구됩니다. 단 자동 로그온 PC는 **물리적 접근 통제가 되는 위치**에 두어야 합니다.

**원격접속 주의**: RDP로 접속했다가 창만 닫으면 세션이 잠깁니다. 운영 PC는 콘솔 세션을 유지해야 하며, 원격 점검 후에는 `tscon`으로 콘솔에 세션을 되돌리는 절차를 운영 수칙에 넣습니다.

## 7. ★ ERP 로그인 자동화 (사용자 확인 2번)

> **"ERP 첫 화면 페이지에 ID/PW를 입력해야 한다. PC 비밀번호와는 다르다."**

SSO가 아니고 OTP도 없으므로 **자동 로그인이 가능한 조건**입니다. 두 가지 모드를 지원하고, 상황에 따라 고를 수 있게 합니다.

### 7.1 모드 A — 완전 자동 로그인 (권장)

```python
# core/session.py
def login():
    app = Application(backend="uia").start(ERP_EXE_PATH)
    win = app.window(title_re=".*존슨일렉트릭.*")
    win.wait("exists visible ready", timeout=60)     # ERP 초기 로딩이 김

    fields.write(win.child_window(auto_id=LOGIN_ID_CTRL), keyring.get_password("ERP", "id"))
    fields.write(win.child_window(auto_id=LOGIN_PW_CTRL), keyring.get_password("ERP", "pw"))
    win.child_window(auto_id=LOGIN_BTN_CTRL).invoke()

    # 로그인 성공 = 메인 메뉴가 뜨는 것으로 확인
    win.child_window(auto_id="PART_txtPgmSearch").wait("exists visible", timeout=60)
```

- **비밀번호는 코드·YAML·환경변수에 두지 않습니다.** Windows 자격 증명 관리자에 저장하고 `keyring`으로 조회합니다.
- 로그인 화면의 `auto_id`는 아직 모릅니다 → **로그인 화면 상태에서 `dump_controls.py`를 한 번 실행**해 확보해야 합니다. (Phase 2 첫 작업)
- **비밀번호 만료 대응**: ERP 계정 비밀번호가 주기적으로 만료되면 어느 날 갑자기 로그인이 실패합니다. 로그인 실패 시 즉시 알림을 보내고, 만료 임박 경고 팝업도 감지 대상에 넣습니다.

### 7.2 모드 B — 세션 상시 유지 (모드 A가 막힐 때)

담당자가 **퇴근 전 ERP를 로그인해 켜둔 채로** 두고, 프로그램은 실행 중인 창에 `connect()`만 합니다 (현행 방식과 동일).

- 장점: 로그인 자동화 불필요, 비밀번호를 PC에 저장하지 않아도 됨
- 단점: 매일 사람의 준비 동작이 필요, ERP 자동 세션 만료 시 실패
- **preflight에서 ERP 창 존재 여부를 확인**해, 없으면 저녁에 미리 알림을 보냅니다 ("오늘 ERP가 안 켜져 있습니다")

### 7.3 권장

**모드 A로 구현하되 모드 B를 폴백으로 둡니다.** 설정 한 줄로 전환되게 만들어, 계정 정책 문제로 자동 로그인이 막히더라도 시스템 전체가 멈추지 않게 합니다.

## 8. 안전장치

| 장치 | 내용 |
|---|---|
| **Dry-run 모드** | 값만 채우고 저장하지 않음. **신규 레시피는 반드시 dry-run 통과 후 운영 투입** |
| **중복 입력 방지** | `dedupe_key` 해시를 SQLite에 유니크 저장. 같은 파일을 두 번 넣어도 재입력 안 됨 |
| **처리 건수 상한** | 1회 최대 N건(예: 300). 초과 시 중단+알림 (소스파일 사고 방지) |
| **킬스위치** | `C:\ERP_Auto\STOP.flag` 존재 시 즉시 중단. 원격에서 파일 하나로 정지 |
| **연속 실패 차단** | 3건 연속 실패 시 전체 중단. 잘못된 상태로 100건을 밀어넣지 않음 |

## 10. 단계별 로드맵

| 단계 | 내용 | 완료 판정 | 예상 |
|---|---|---|---|
| **1. 골격 + UIA 전환** | 레시피 로더 · `fields.py` 3단 폴백 · 상태DB. **기존 근태 화면을 레시피로 재현**해 현행과 결과가 같은지 검증 | 근태 10건 dry-run 성공, 컨트롤별 동작 단계 실측 완료 | 2주 |
| **2. 로그인 + 각성 유지** | 로그인 화면 컨트롤 덤프 → 자동 로그인 · `awake.py` · `ScreenSaverIsSecure` 확인 | **화면보호기 시간을 2분으로 줄여놓고 30분 방치 테스트 통과** | 1~2주 |
| **3. 무인 실행** | 스케줄러 · preflight · 공용폴더 스캔 · 리포트 · 알림 | 야간 무인 3일 연속 성공 | 1주 |
| **4. 안전장치** | 저장 검증 · 팝업 감시 · 중복 방지 · 킬스위치 · 워치독 | 의도적 실패 주입 테스트 통과 | 1주 |
| **5. 양식 생성기 + 부서 확산** | `make-template` · 부서별 레시피 추가 | 부서당: dry-run → 1주 병행 → 단독 전환 | 부서당 2~3일 + 병행 1주 |

**2단계의 완료 판정**을 특히 강조합니다. 화면보호기 문제는 "돌려보니 되던데요"로 끝내면 안 되고, **일부러 화면보호기가 뜨는 조건을 만들어 통과하는지 확인**해야 합니다. 이 검증을 건너뛰면 실제 야간 운영 첫날 실패합니다.

## 11. 남은 확인 사항

1. **대상 부서·메뉴 목록과 건수** — 어떤 부서가 어떤 메뉴에 무엇을 입력하는지, 일 평균 몇 건인지. 건당 2~4초 기준이므로 하루 1,000건이면 약 1시간입니다. 수천 건 규모면 야간 시간 배분을 다시 계산해야 합니다.
2. **`ScreenSaverIsSecure` 값** (6.5) — 이것 하나가 야간 무인 실행의 성립 여부를 가릅니다. 위 `reg query` 명령 결과만 알려주시면 됩니다.
3. **운영 PC** — 전용 PC를 둘 수 있는지, 아니면 특정 담당자 PC를 쓰는지. 후자라면 퇴근 시 로그오프하지 않는 수칙이 필요합니다.
4. **알림 채널** — 사내 메일(SMTP 서버 주소 필요) / Teams Webhook / 둘 다 중 무엇인지.
5. **실패 시 정책** — 1건 실패 시 나머지를 계속 진행할지, 전체 중단할지. 부서별로 다르게 둘 수도 있습니다.
6. **ERP 실행 파일 경로와 로그인 화면** — 모드 A 구현에 필요합니다. 로그인 화면이 뜬 상태에서 `dump_controls.py`를 한 번 실행해 주시면 바로 진행할 수 있습니다.
